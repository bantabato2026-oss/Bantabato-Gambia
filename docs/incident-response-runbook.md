# Incident Response Runbook

This is a preparation document, not evidence that an incident process has been rehearsed. Do not contact members or providers from this document.

| Incident                    | Detection                                      | Immediate containment                                      | Authorization boundary          | Evidence preservation                         | Escalation / recovery                     | Member communication           |
| --------------------------- | ---------------------------------------------- | ---------------------------------------------------------- | ------------------------------- | --------------------------------------------- | ----------------------------------------- | ------------------------------ |
| Account compromise          | Suspicious authentication/session event        | Revoke affected sessions; require fresh auth               | Member/security authority only  | Request IDs, timestamps, minimal audit events | Security owner; restore account safely    | Pending owner-approved message |
| Unauthorized access         | Authorization anomaly or staff denial spike    | Preserve fail-closed access; revoke session if appropriate | Role and permission policy      | Minimal event envelope; no private payload    | Security owner; review policy             | Pending                        |
| Privacy/data exposure       | Storage, projection, export, or log alert      | Stop affected path and public access                       | Privacy/security authority      | Object/request identifiers only               | Privacy/legal + security owner            | Pending                        |
| Identity verification issue | Verification workflow failure or report        | Keep verification decision fail-closed                     | Verification role boundary      | Case identifier and status only               | Trust & Safety owner                      | Pending                        |
| Messaging abuse             | Member report or abuse signal                  | Apply existing report/block/restriction controls           | Member safety policy            | Report metadata, not message content          | Trust & Safety owner                      | Pending                        |
| Safety report               | Safety case creation or workflow failure       | Preserve safety state and restrict unsafe action           | Trust & Safety/four-eyes policy | Case metadata and audit trail                 | Safety owner                              | Pending                        |
| Staff privilege issue       | Role-boundary violation or revoked-session use | Revoke staff session and deny action                       | Admin operations policy         | Minimal audit event                           | Security + operations owner               | Pending                        |
| Database failure            | Health/database connectivity signal            | Stop unsafe mutations; verify identity                     | Infrastructure authority        | Health/request IDs only                       | Infrastructure owner; restore if verified | Pending                        |
| Storage failure             | Upload/read failure                            | Keep objects private; disable affected path                | Storage authority               | Non-sensitive object operation code           | Infrastructure owner                      | Pending                        |
| Deployment failure          | Failed health/build/migration                  | Stop rollout and use verified rollback target              | Deployment authority            | Version and migration IDs                     | Technical + infrastructure owner          | Pending                        |
| Backup/restore failure      | Integrity or restore validation failure        | Do not claim recoverability; preserve source               | Recovery authority              | Artifact/checksum metadata                    | Backup owner                              | Pending                        |
| Notification failure        | Provider-neutral delivery or queue error       | Keep in-app security notices; stop unsafe retries          | Notification policy             | Event type and idempotency key only           | Operations owner                          | Pending                        |

Every response must preserve member privacy, staff role boundaries, fresh-auth requirements, stale-write protection, four-eyes approval, and provider-neutrality.
