# BANTABATO — Major Product Capability Sprint 30

## Trust, Profile Credibility & Verification UX

Sprint 30 strengthens the member journey from profile completion through discovery, introductions, and connection readiness without inventing a score, ranking, safety claim, or external service. It adds a reusable **Profile Credibility Panel** that separates four factual current signals: profile foundation, the five-approved-photo requirement, manual identity-document review, and marriage-preference completion. The panel explicitly says these are not a Trust Score, popularity signal, safety guarantee, character judgment, compatibility promise, Premium advantage, or access to private documents.

Private identity-document submission now carries the last observed identity-record identifier. The server locks the member workflow, checks that the latest record is still the one the form observed, retains existing open-review duplicate recovery, and rejects a stale submission without storing another document. The member sees only a plain-language refresh/review/retry message. Document storage remains private; no public URL, storage key, document preview, staff reason, or reviewer note is exposed in member, discovery, recommendation, message, Family Circle, notification, profile-preview, ordinary staff-summary, or account-data views.

The five-photo journey now supplies an accessible label, live status, selected-file cancellation, explicit destructive removal confirmation, safe error mapping, offline boundaries, and server-confirmed state. Upload sends the observed private photo count; removal sends the observed photo version. The server preserves capacity enforcement, profile ownership, audit evidence, and eligibility synchronization while rejecting stale upload or removal attempts. Removing a photo continues to recalculate eligibility, discovery, recommendation, connection, and permitted profile-presentation state through existing server authority; it never converts another photo to approved or erases review history.

Identity-review copy now consistently says “Identity review completed” rather than relying on a broad “verified” label, and states that manual document approval does not guarantee safety, compatibility, character, conduct, or relationship outcome. Existing discovery, recommendation, profile detail, connection readiness, block/report/restriction/suspension, consent, privacy, international, country, Family Circle, notification, and Premium-neutral boundaries remain intact.

Focused source and policy coverage includes no-score credibility wording, private-document isolation, stale/duplicate submission protection, photo count/version guards, eligibility propagation, safety precedence, notification privacy, staff and Family Circle isolation, country/diaspora neutrality, accessible input/confirmation/status treatment, and offline recovery. The full validation passed: **415 tests across 85 files**, TypeScript, production build, and production dependency audit. Desktop and 375px mobile visual review were read-only. The existing preview member has no started profile, so the review truthfully covered responsive prerequisite, empty, and unavailable recovery states; it did not upload a file, remove a photo, submit a document, change privacy, create a connection, or create test activity.

## Product classification

Bantabato’s internal trust journey is more understandable and resilient, with stronger stale-action protection for the current private document and profile-photo paths. It is **not launch ready**. Remaining genuine product gaps include authorized, policy-backed document retention/deletion operations, documented reviewer service-level procedures, approved multilingual trust copy, consented usability testing with real prospective members, and operational readiness across support, moderation, and compliance workflows.
