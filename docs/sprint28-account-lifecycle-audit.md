# Sprint 28 Account Lifecycle, Privacy Controls & Data Rights Audit

## Review boundary

The audit read the existing profile, visibility, eligibility, notification, international, authentication, and database patterns. It captured read-only desktop and 375px mobile views for Settings, Profile, Profile Preview, Device & data, International, Notifications, Family Circle, and Safety Center. The preview account did not have a completed profile, so protected pages showed factual prerequisite or empty states. No profile, privacy, language, notification, Family Circle, safety, document, session, payment, or browser mutation was made.

## Existing usable foundations

Member profile settings already have server-authoritative, observed-version protection for profile visibility, photo visibility, discovery visibility, and Family Circle visibility. Those changes revoke recommendations and incompatible connections where necessary. Discovery and recommendations already exclude paused, hidden, deleted, or ineligible profiles. The eligibility policy preserves `paused` and `suspended` states and makes discovery unavailable when a member leaves discovery. Profile photos are private, five approved photos remain the factual eligibility rule, identity documents remain private, notification preferences preserve essential in-app categories, and international settings already control country/location detail visibility.

Existing mobile surfaces use labeled cards, readable summaries, responsive controls, and clear factual prerequisite states. The current Settings route is intentionally sparse: it links only Privacy controls, Notifications, Device & data, and relationship declaration. It does not clearly distinguish profile choices from account controls or offer member-owned account lifecycle, data-rights, session, or destructive-action journeys.

## Genuine gaps selected for implementation

There is no member account-state model, lifecycle event history, session-management projection, member data-rights request/status record, deletion-request state, or consolidated Privacy Center. Existing profile visibility controls are distributed across profile, photos, international, preferences, Family Circle, and notifications. Current login uses Manus OAuth and only has current-session sign-out; recovery, external verification, and other-session revocation are not internally available. The existing fresh-authentication policy can be reused for high-impact deletion requests, but no deletion request should silently delete retained legal, safety, audit, or operational records.

## Boundary decisions

Sprint 28 must use additive, member-owned server records and keep pending deletion and data-rights requests provider-neutral. A requested data export must never be presented as a generated file. Profile deletion is not currently supported; a deletion request may only remove the member’s discovery projection immediately and remain a request until an authorized policy process exists. A paused account may resume only through existing eligibility synchronization; suspension, restriction, blocks, reports, eligibility, and connection authorization continue to take precedence. Current-session sign-out is supported; recent sessions and other-session revocation may be represented only as unavailable unless a real session ledger is implemented. No member or staff private record, document key, safety reason, other member data, credential, or signed media URL may appear in account or data-rights views.

## Implemented result and final review

Sprint 28 adds an additive schema migration for member account state, append-only minimized lifecycle events, and provider-neutral data-rights requests. The protected Account Center separates account controls from profile settings and adds a Privacy Center with clear effects for profile, discovery, photo, and Family Circle visibility. It also connects established location, verification, recommendation, notification, device, membership, safety, and Family Circle settings without broadening their authority.

Pause applies a server-authoritative `paused` profile state and removes discovery/recommendation projection. Reactivation restores only the prior ordinary profile state and then re-runs existing eligibility synchronization; it never restores a suspension or bypasses safety, consent, readiness, blocks, or other authority. A fresh-sign-in deletion request immediately removes discovery projection and revokes current connections and related Family Circle shares through existing authorization paths, but remains a request rather than a deletion claim. Data requests use factual requested, processing, ready, expired, cancelled, unavailable, and failed states. No file is made available or represented as generated.

Focused policy and contract tests cover pause, reactivation, fresh-auth deletion, request cancellation, stale observed-version guards, transaction locking, protected ownership, cross-module withdrawal, current-session limitations, privacy effects, offline confirmation, accessibility, and premium neutrality. Final validation passed TypeScript, **399 tests across 82 files**, a production build, and the production dependency audit. Desktop and mobile review remained read-only. The generic preview browser had no authenticated member session and correctly presented the sign-in gate for `/app/account`; no login, account, privacy, data-rights, session, profile, document, message, Family Circle, safety, or browser mutation was performed. A separate preview Settings view confirmed the new account-versus-profile handoff card and its desktop hierarchy.
