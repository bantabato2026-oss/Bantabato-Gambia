# BANTABATO — Communication & Authenticated Experience Polish Audit

**Scope:** Existing private conversation, voice-note, discovery, shared-state, mobile, accessibility, and server-regression implementation. This audit does not alter matching logic, provider capability, or operational readiness.

| Area | Existing verified foundation | Verified internal gap | Checkpoint action |
| --- | --- | --- | --- |
| Voice-note capture | Browser support/permission explanation, three-minute cap, timer, pause/resume, cancel, private preview, private upload, retry copy, signed playback, sender deletion, report control, and server ownership/mutual-match enforcement exist. | Lifecycle states are implicit in controls; no lightweight visual waveform, explicit upload/sending/permission/restricted recovery panel, playback progress display, or consistent low-bandwidth visual alternative. | Add a client-only visual waveform, labelled lifecycle status, recovery guidance, upload/send feedback, and progress display without changing media upload or server gates. |
| Message composer | Text drafts are device-local, send follows the existing mutation, offline submit is refused, and report/block/pause/mute controls exist. | Conversation loading uses generic pulse; query failures can resemble an empty conversation; composer does not present an in-surface network recovery state. | Use StateSkeleton/StatePanel, a factual composer status, and retry actions for safe read-query recovery. |
| Voice playback | Private signed URL query, native audio controls, duration, report, and owner-only delete exist. | Native controls do not give a bespoke loading/error state or visible playback progress in the surrounding Bantabato surface. | Add a lightweight accessible player wrapper with progress text/slider while retaining native audio and signed URL behavior. |
| Discovery | Curated, deterministic/no-score collections, filtering, privacy-safe profile cards, compatibility explanation, eligible-profile guard, and empty message exist. | Generic skeletons and no explicit read-query error/retry state. | Replace generic cards with StateSkeleton and StatePanel error/retry; add a restrained compatibility-explanation transition without ranking changes. |
| Authenticated complex states | Shared `StatePanel`/`StateSkeleton`, auth shells, representative recovery panels, reduced-motion, and low-bandwidth suppression already exist. | Messaging, discovery, and some conversation-detail loading/recovery still use local pulse/empty fallbacks. | Adopt existing shared primitives only at the verified gaps. |
| Accessibility and mobile | Visible focus, keyboard-native controls, mobile shell/navigation, draft preservation, state semantics, and server security regressions exist. | No consolidated authenticated accessibility matrix for communication controls; no focused source contract for waveform/lifecycle labels and mobile composer safeguards. | Add matrix and focused contracts; label unavailable assistive-technology execution accurately. |

## Explicit non-goals

This checkpoint must not introduce live calling, background recording, external audio processing, transcription, popularity/engagement/compatibility scoring, provider activation, private-media preloading, public voice media, new server authorization pathways, or a retry that replays a high-impact action automatically.
